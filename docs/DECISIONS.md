## Model and engine

| ID | Decision | Why |
| --- | --- | --- |
| D-05 | **Normalised coordinates.** Every position is `x, y` in 0…1 on the pitch: `x` left to right, `y` from your own goal line (0) to the opponent's (1). The pitch type (full, 7-a-side, 5-a-side) sets the aspect ratio. Points and pixels exist only in `Render/`. | One tactic draws correctly on any screen, at any export size, on any pitch. It also makes the file format small and readable. |
| D-06 | **Keyframe steps, pure timeline.** A tactic is an ordered list of steps; each step holds every token's position, plus optional paths and arrows. `Timeline.state(at:in:)` is a pure function: hold 0.3 s on each step, then move to the next over the step's duration (default 1.2 s) with ease-in-out. A token with a path follows the path; otherwise it moves in a straight line. | Steps are how coaches already think ("then the full-back overlaps"). A pure function makes playback, scrubbing, export and tests agree, and makes timing testable without a clock. |
| D-07 | **One renderer.** `BoardRenderer` draws with Core Graphics into a `CGContext`. The screen uses it inside `Canvas` via `GraphicsContext.withCGContext`; export uses the same code on an offscreen context. | The PRD's split (Canvas on screen, something else for export) invites "looks different in the video" bugs. `ImageRenderer` can't render UIKit-backed views like PencilKit. One renderer means the export matches by construction. |
| D-08 | **PencilKit is capture only.** A drawn stroke is simplified (Douglas–Peucker, then capped at 200 points) into our own `Path` model: either a token's run for that step, or a free annotation. Export never renders a `PKDrawing`. | Vector data animates, exports at any size and fits in the file format. A `PKDrawing` blob would bloat files and links and couldn't drive a token. |
| D-09 | **Document-based app.** `DocumentGroup` + `FileDocument` (`TacticDocument`) reading and writing `.tactic` JSON, with an exported UTType (`dev.chime.tacticsboard.tactic`, extension `.tactic`, conforming to `public.json`). The system document browser is the library, with a custom launch scene. | Free Files, iCloud Drive and AirDrop integration, and no library UI to build. It also proves the open format in the portfolio. |
| D-10 | **Links without a server.** A tactic link is `tacticsboard://t#v1.<base64url(zlib(json))>` and the same string in a QR code. No universal links. A GitHub Pages viewer is a stretch goal after the repo is public. | Free provisioning can't use Associated Domains, so universal links are out. The data stays in the fragment; nothing is uploaded. |
| D-11 | **Video export: MP4, H.264, 30 fps.** Presets 1080×1920 (9:16, default), 1080×1080 and 1920×1080. Caption safe zones are drawn in the export preview only. Target under 8 MB for 15 seconds; show the size before sharing. | 9:16 is the gap (D-02). H.264 plays everywhere, including WhatsApp. Small files matter on Lagos mobile data (PRD). |

## Design and content

| ID | Decision | Why |
| --- | --- | --- |
| D-12 | **Design phase first** (Day 1). Reference screenshots stay local (git-ignored). Reference images are other apps' copyrighted UI. |
| D-13 | **No real-world IP.** No club badges, league names, real kits, player photos or databases, game logos or screenshots. Kit colours come from a neutral palette. Users type any names they like. Roles and presets are written in our own words. | Apple expects you to own or license IP in an app; lineup apps lean on club looks and we won't. It also keeps the open-source repo clean. |
| D-14 | **Presets ship as data.** `presets/formations.json` (8 eleven-a-side shapes plus 5- and 7-a-side) and `presets/roles.json` (about 20 generic roles) are the source; the app bundles copies. Applying a formation keeps each token's name and number and moves it to the new slot. | Editable without code changes, testable, and reusable by Five-a-Side later. |
| D-15 | **Sides differ by shape, not only colour.** Home tokens are filled discs, away tokens are rings, the ball is a small white disc with a dark outline. Arrows: run = solid with a head, pass = dashed, dribble = wavy, press = short double chevron. | Accessibility (colour-blind users, greyscale video) and coaching convention. |
| D-16 | **Vertical pitch by default**, attacking upward, on iPhone and in 9:16 export. iPad shows the same vertical pitch in the centre column; a horizontal pitch is a Should for 16:9 export. | Phones are held upright and 9:16 is the hero export. One orientation halves the layout work this week. |

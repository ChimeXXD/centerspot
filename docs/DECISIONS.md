# Decisions

Written 6 Nov 2026 from the PRD (25 Oct), the shortlist research (5 Nov) and what Meridian taught us. Claude CLI treats them as fixed. To change one, add a new entry that supersedes it rather than editing the old one.

## Frame

| ID | Decision | Why |
| --- | --- | --- |

## Model and engine

| ID | Decision | Why |
| --- | --- | --- |
| D-05 | **Normalised coordinates.** Every position is `x, y` in 0…1 on the pitch: `x` left to right, `y` from your own goal line (0) to the opponent's (1). The pitch type (full, 7-a-side, 5-a-side) sets the aspect ratio. Points and pixels exist only in `Render/`. | One tactic draws correctly on any screen, at any export size, on any pitch. It also makes the file format small and readable. |
| D-06 | **Keyframe steps, pure timeline.** A tactic is an ordered list of steps; each step holds every token's position, plus optional paths and arrows. `Timeline.state(at:in:)` is a pure function: hold 0.3 s on each step, then move to the next over the step's duration (default 1.2 s) with ease-in-out. A token with a path follows the path; otherwise it moves in a straight line. | Steps are how coaches already think ("then the full-back overlaps"). A pure function makes playback, scrubbing, export and tests agree, and makes timing testable without a clock. |
| D-07 | **One renderer.** `BoardRenderer` draws with Core Graphics into a `CGContext`. The screen uses it inside `Canvas` via `GraphicsContext.withCGContext`; export uses the same code on an offscreen context. | The PRD's split (Canvas on screen, something else for export) invites "looks different in the video" bugs. `ImageRenderer` can't render UIKit-backed views like PencilKit. One renderer means the export matches by construction. |
| D-08 | **PencilKit is capture only.** A drawn stroke is simplified (Douglas–Peucker, then capped at 200 points) into our own `Path` model: either a token's run for that step, or a free annotation. Export never renders a `PKDrawing`. | Vector data animates, exports at any size and fits in the file format. A `PKDrawing` blob would bloat files and links and couldn't drive a token. |
| D-09 | **Document-based app.** `DocumentGroup` + `FileDocument` (`TacticDocument`) reading and writing `.tactic` JSON, with an exported UTType (`dev.chime.tacticsboard.tactic`, extension `.tactic`, conforming to `public.json`). The system document browser is the library, with a custom launch scene. | Free Files, iCloud Drive and AirDrop integration, and no library UI to build. It also proves the open format in the portfolio. |
| D-10 | **Links without a server.** A tactic link is `tacticsboard://t#v1.<base64url(zlib(json))>` and the same string in a QR code. No universal links. A GitHub Pages viewer is a stretch goal after the repo is public. | Free provisioning can't use Associated Domains, so universal links are out. The data stays in the fragment; nothing is uploaded. |
| D-11 | **Video export: MP4, H.264, 30 fps.** Presets 1080×1920 (9:16, default), 1080×1080 and 1920×1080. Caption safe zones are drawn in the export preview only. Target under 8 MB for 15 seconds; show the size before sharing. | 9:16 is the gap (D-02). H.264 plays everywhere, including WhatsApp. Small files matter on Lagos mobile data (PRD). |

## Design and content

| ID | Decision | Why |
| --- | --- | --- |
| D-12 | **Design phase first** (Day 1). Collect references (football apps, board and drawing tools, video editors) into `docs/design/REFERENCES.md`; build three directions as an HTML direction board; Chime picks one; then complete `docs/design/UI-BRIEF.md` and the design tokens. Reference screenshots stay local (git-ignored). After that **the app is the source of truth**; Chime may sketch in Figma, but the SwiftUI wins. | Meridian's design pass (style board → direction board → UI brief) worked, and Chime wants to start with design. Reference images are other apps' copyrighted UI. |
| D-13 | **No real-world IP.** No club badges, league names, real kits, player photos or databases, game logos or screenshots. Kit colours come from a neutral palette. Users type any names they like. Roles and presets are written in our own words. | Apple expects you to own or license IP in an app; lineup apps lean on club looks and we won't. It also keeps the open-source repo clean. |
| D-14 | **Presets ship as data.** `presets/formations.json` (8 eleven-a-side shapes plus 5- and 7-a-side) and `presets/roles.json` (about 20 generic roles) are the source; the app bundles copies. Applying a formation keeps each token's name and number and moves it to the new slot. | Editable without code changes, testable, and reusable by Five-a-Side later. |
| D-15 | **Sides differ by shape, not only colour.** Home tokens are filled discs, away tokens are rings, the ball is a small white disc with a dark outline. Arrows: run = solid with a head, pass = dashed, dribble = wavy, press = short double chevron. | Accessibility (colour-blind users, greyscale video) and coaching convention. |
| D-16 | **Vertical pitch by default**, attacking upward, on iPhone and in 9:16 export. iPad shows the same vertical pitch in the centre column; a horizontal pitch is a Should for 16:9 export. | Phones are held upright and 9:16 is the hero export. One orientation halves the layout work this week. |

| D-22 | **Design straight in SwiftUI, no Figma pass.** Direction board (HTML) → Chime picks → UI brief → tokens → SwiftUI screens approved from simulator screenshots. Replaces PROCESS.md design step 5 for this project; D-12 stands. | Chime, 6 Nov: "No, we're designing straight on SwiftUI." The case study shows the direction board and the approved screens instead of Figma files. |
| D-23 | **Day 1 runs two lanes:** design direction (Chime's picks) and the core, tests first (model, format, import validation, timeline, presets, `Placement`: the old Day 2 list). They touch different files. Day 2 finishes whichever lane spilled over, then starts the board renderer, so the week gains about a day of buffer for export and drawing. | Chime, 6 Nov, agreed ("Yes, it is okay"). The core doesn't depend on the look; Meridian ran design and data clients in parallel on its Day 2. |
| D-24 | **Screen vs export render check uses a tolerance**, not pixel-for-pixel: frames at the same `t` and size must have at least 99.5% of pixels within 2/255 per channel. Changing these numbers needs Chime's OK. | Chime agreed, 6 Nov. Colour space, scale and anti-aliasing differ slightly between `Canvas` and an offscreen context without being bugs; a pixel-exact test would fail for the wrong reasons. Revisit if a real visual difference passes. |
| D-25 | **Link payload is raw DEFLATE (RFC 1951, no zlib header)**, base64url without padding: `tacticsboard://t#v1.<base64url(deflate(json))>`. Supersedes the encoding wording in D-10; the rest of D-10 stands. | Chime agreed, 6 Nov. Checked the same day: `NSData.compressed(using: .zlib)` output starts `ab 56` (no zlib header); Python's `zlib.decompress` rejects it, `zlib.decompress(b, -15)` decodes it. Naming the exact encoding keeps the open format honest for other tools. |
| D-26 | **iPad testing uses Chime's brother's iPad and Apple Pencil**, signed with Chime's free Apple ID, in planned borrow sessions (drawn runs on Day 4, harden on Day 6, filming on Day 7). Chime's iPhone 14 Pro is the everyday device; finger drawing on iPhone is the always-available path. Needs iPadOS 26 or later on that iPad. | Chime, 6 Nov: "I don't have an iPad or Apple Pencil, but my brother does." Pencil-drawn runs stay a selling point (D-02) only if a borrow session proves them. Narrows O-3. |
| D-27 | **Import has two outcomes, written per field in `FORMAT.md`:** structure and safety problems *refuse* the file with a plain error; cosmetic values are *repaired* (clamp, truncate, drop). An empty board (0 tokens) is valid. Runs are *anchored* on read (first point = this step's position, last point = next step's), so playback can't jump. Links inflate with a streaming decoder that stops at 256 KB. | Fresh-context spec review, 6 Nov: without this, most import rules had no defined result to test, an empty board saved by the app would fail to reopen, and one-shot decompression let a decompression bomb through. Engineering detail under CLAUDE.md rule 4; Chime may veto. |
| D-28 | **Drawing a run moves the token's next-step position to where the stroke ends**, adding a next step if there is none. Resolves O-5. | Chime, 6 Nov: "For [O-5], yes, I agree." What you draw is where the player goes. |

## Lessons carried from Meridian

| ID | Lesson | How it applies |
| --- | --- | --- |
| L-1 | Renders are not enough; a layout bug only showed on the device. | Check drag feel, Pencil latency, playback and exported files on the real iPhone and iPad before a gate passes. |
| L-2 | Tests first on the core logic caught real bugs (time zones there). | Tests first for coordinates, timeline, paths, codec and import validation. |
| L-3 | A numbered decisions log kept many sessions consistent. | This file. Supersede, never edit. |
| L-4 | Parallel agents collided on one simulator. | One simulator at a time; Split It runs in parallel, so share the Mac carefully. |
| L-5 | Honest numbers read as senior (14 of 18, then 20 of 20). | Publish real export timings and file sizes in the case study, including misses. |

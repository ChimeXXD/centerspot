## What we are building

An iPhone and iPad app that turns a formation into a **step-by-step animated move** and exports it as a **vertical video**, an image or a `.tactic` file. One line: **"Draw the move, not just the shape."**

- Users: FM and EA FC players explaining a tactic, Sunday-league and five-a-side coaches, football creators who need a 9:16 clip.
- The edge (D-02): keyframe steps, one-tap 9:16 MP4, Pencil-drawn runs, and an open tactic format. No competitor does all four.
- Primary user: Chime in Lagos, on an iPhone first, then an iPad.
- Original PRD and research: `docs/PRD.md`, `docs/RESEARCH.md`. Full spec: `docs/SPEC.md`. File format: `docs/FORMAT.md`.

## Stack (fixed)

- Swift 6 with strict concurrency, SwiftUI, **iOS and iPadOS 26.0 minimum** (D-03). iOS 27 APIs (image input to the on-device model) sit behind `#available`.
- One universal app target, `Agmen` (iPhone and iPad). No widget extension this week.
- **Own library, `.tactic` files** (D-56, supersedes D-09's system browser): a `WindowGroup` with Agmen's library screen; tactics are `.tactic` JSON files in the app's Documents folder (`Services/TacticLibrary`), opened into the board through `TacticDocument` with the board's own `UndoManager` and autosave. `.tactic` files from AirDrop, WhatsApp or Files are validated and copied in.
- **One renderer** (D-07): `BoardRenderer` draws with Core Graphics into a `CGContext`. The screen calls it through `GraphicsContext.withCGContext` inside `Canvas`; export calls it on an offscreen context. Never draw the board twice in two ways.
- PencilKit is **capture only** (D-08). Strokes become our own path model; export never renders a `PKDrawing`.
- Video: `AVAssetWriter` + `AVAssetWriterInputPixelBufferAdaptor`, H.264, 30 fps (D-11).
- The project is generated by **XcodeGen** from `project.yml`. Never hand-edit `.xcodeproj` (git-ignored). Edit `project.yml`, then `xcodegen generate`.
- IDs and signing live in `Config/Base.xcconfig`. The Team ID goes only in the git-ignored `Config/Signing.local.xcconfig`. Never commit a Team ID.
- Tests use Swift Testing (`import Testing`). **No third-party dependencies.** Any new package needs Chime's OK.

## Rules that protect correctness

1. **Positions are normalised pitch coordinates** (`x`, `y` in 0…1): `x` left to right, `y` from your own goal line (0) to the opponent's (1), attacking upward. Convert to points only in `Render/`. Never store points or pixels (D-05).
2. **The timeline is a pure function**: `Timeline.state(at: t, in: tactic) -> BoardState`. No timers, no randomness, no `Date()`. Playback, scrubbing, export and tests all call it, so what plays is what exports (D-06).
3. **Screen and export share `BoardRenderer`** (D-07). A change to how the board looks goes into `Render/` once. A render test compares an on-screen-sized frame with the exported frame at the same `t`.
4. **Never trust an imported file.** Cap `.tactic` files and decoded links at 256 KB, check `schemaVersion`, clamp coordinates to 0…1, and limit tokens (≤ 30), steps (≤ 40) and path points (≤ 200 per path). A bad file shows a plain error, never a crash (`docs/FORMAT.md`).
5. **No real-world IP** (D-13): no club badges, league names, real kits, player photos, game logos or game screenshots in the app, the repo or the demo. Users may type any names. Presets and roles use our own words (`presets/`).
6. **Colour is never the only difference between sides** (D-15): home tokens are filled, away tokens are rings. Arrow kinds differ by line style (run solid, pass dashed, dribble wavy), not only colour.
7. **Exports are honest about size**: show the file size before sharing. Target under 8 MB for a 15-second 1080×1920 clip (D-11).
8. **Reduce Motion** changes in-app playback to step-through with crossfades. It never changes an exported video.
9. **Renders are not enough.** Check drag, Pencil, playback smoothness and export on the real iPhone (and iPad) before calling them done. Meridian's widget bug only showed on the device.

## Working style

- Work day by day from `docs/PLAN.md`. Pass a day's gate before starting the next.
- **Tests first** for everything in `Model/`, `Engine/` and `Services/LinkCodec` (codec round trips, interpolation, clamping, format validation). Fixtures are `.tactic` files in `AgmenTests/Fixtures/` (start from `examples/`).
- Commit after each green step with a conventional message (`feat:`, `fix:`, `test:`, `chore:`, `docs:`). Push to GitHub after every commit (private repo until Day 7).
- After UI work: build, take a simulator screenshot, and compare with the approved baseline before calling the step done.
- Update the checkbox in `docs/PLAN.md` and the matching item in `docs/features.json` (with evidence) when a task is complete. Log each session in `PROGRESS.md` (newest first) and rewrite `docs/HANDOFF.md` at the end of each session.
- New product or architecture choices get a numbered entry in `docs/DECISIONS.md` (supersede, never edit, old entries).
- Keep files under about 300 lines; one type per file in `Model/`.
- Accessibility: every token has a VoiceOver label in football words built from its role and zone ("Number 9, striker, edge of the box, step 3"). Every control has a label; Dynamic Type works in every sheet.
